# Заняття 1 Один товар у браузері та базі

Результат: пояснити компоненти й зіставити товар у UI та PostgreSQL. Час — 35–50 хвилин. Магазин і DBeaver уже запущені; повторна установка або seed не потрібні.

## Пригадування

Своїми словами поясни: що запускає Docker; де працюють Medusa й Next.js; що зупиниться після Ctrl+C і чи збережуться товари? Це перевірка розуміння після вже виконаного запуску.

## Крок 1 Спостереження у браузері

Відкрий http://localhost:8000/dk/products/sweatshirt. Запиши URL, назву, відображену ціну, доступні розміри, чи вибраний розмір і напис кнопки додавання. Раніше на скриншоті було Medusa Sweatshirt, From €10.00 та Out of stock без вибраного розміру. Поточний стан перевір сам.

Натисни M та запиши зміну. Додавання й checkout залишимо наступним вправам. Out of stock — спостереження; причина та правильність ще не встановлені.

## Крок 2 Той самий товар у DBeaver

Знайди public.product, відкрий Data й рядок із handle sweatshirt. У SQL Editor сам напиши SELECT для id, title, handle з умовою за handle. Ментор дає синтаксичну підказку після спроби, якщо потрібна.

Зістав title з UI, handle з URL. У Properties перевір тип id і в Constraints — наявність первинного ключа. Назва id сама по собі не доводить тип integer або PK. Ціни та inventory мають окрему модель, яку дослідимо пізніше.

## Крок 3 Шлях даних

Намалюй браузер → Next.js → Medusa → PostgreSQL і окремо DBeaver → PostgreSQL. Познач порти 8000, 9000, 5432. Поясни, чи потрібна Medusa для перегляду бази в DBeaver, і чому браузерний Network може не показувати прямий запит до Medusa.

## Артефакт і критерії

Надішли спостереження до/після M, запит і результат, тип id/PK та схему. Можна зберегти в docs/learning/submissions/lesson-01.md. Не надсилай env, паролі, cookies чи дані користувачів.

Успіх: знайдено правильний товар; запит має конкретну умову; title/handle зіставлено; тип і ключ перевірено; ролі компонентів пояснено. Після розбору застосуй один SELECT до іншого товару самостійно.

Для 15 хвилин виконай лише пригадування та крок 1. Якщо стан середовища змінився, діагностика до 15 хвилин, потім явно позначений підготовлений приклад. Не запускай другий npm run dev поверх існуючого. Desktop-кейс додаємо лише якщо потрібна окрема діагностика тестового підходу.
